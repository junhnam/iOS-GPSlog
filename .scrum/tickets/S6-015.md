## ユーザーストーリー

ユーザー（jun さん）として、**朝に出かけて自宅に戻った後、その日のうちに再度出かけた時にも、移動経路が自動的に記録されてほしい**。なぜなら、「常時同期 ON にしているのに、知らないうちに記録が止まっている」状態は、後で履歴を見返した時に「行ったはずの場所が空白」になり、本アプリのコア価値（無意識の移動記録）を完全に毀損するから。

---

## 背景（実機検証 / 2026-05-11）

jun さんが iPhone 16 Pro 実機で 2026-05-11 に行った 1 日通しの実利用検証で発覚したバグ。

### 観測された事象

- 朝の出発（自宅 → 外出先）はルート / ピンともに記録された
- 自宅に帰宅後、その日のうちに再度外出（**約 40km 移動**）したが **完全に拾われなかった**
- アプリをタスクキル（スワイプアップでアプリスイッチャーから終了）していたタイミングがあった可能性あり

### 期待される挙動

- 「常時同期 ON」かつ「自宅外」になった時点で、タスクキル状態であっても SLC（Significant Location Changes）でアプリが起床し、通常 GPS 記録が再開される

### 実際の挙動

- SLC で起床しても通常 GPS の `startUpdatingLocation()` が呼ばれず、移動が記録されない

---

## 根本原因（メイン代行が特定済）

**実装漏れ 2 箇所の複合**:

### 原因 1: `LocationService.handleHomeStateTransition`（line 514-527）の条件不足

```swift
} else if previous == .atHome {  // ← この条件が問題
    stopSignificantChanges()
    if !isUpdating { manager.startUpdatingLocation() }
}
```

タスクキル後の SLC 起床では、`lastHomeState` が **メモリから消えて `.unknown` に戻る**。
SLC で起床して自宅外（`.away`）と判定されても、`previous == .atHome` が false（実際は `previous == .unknown`）になるため、通常 GPS が再開されない。

期待: `previous` が `.atHome` の場合だけでなく、`.unknown` から `.away` に遷移した場合にも通常 GPS を再開すべき。

### 原因 2: SLC 起床経路で `resumeTrackingAfterRelaunch` が呼ばれない

`resumeTrackingAfterRelaunch()`（S6-006 で導入された保険ロジック）は `RootView.onChange(of: scenePhase)` でしか呼ばれていない。

バックグラウンド SLC 起床時は **scenePhase が `.active` にならない** ため、保険ロジック側でも記録復元が走らない。結果、`handleHomeStateTransition` の条件不足を補えていない。

## 技術メモ

### `lastHomeState` のライフサイクル

`lastHomeState` は `LocationService` のメモリ上プロパティで、永続化されていない。
そのため、以下のタイミングで `.unknown` にリセットされる:

- アプリのコールドスタート（初回起動 / OS による kill 後の起床）
- ユーザーによるタスクキル後の再起動
- アプリプロセスが OS によって終了された後の SLC 起床

S6-006 で `wasTracking` フラグは `UserDefaults` に永続化したが、`lastHomeState` は永続化対象ではなかった。

**選択肢**:
- A: `lastHomeState` も `UserDefaults` に永続化する
- B: `previous == .atHome` 条件を緩和する（`.unknown` も含める）

→ **B を採用**（dev-2 判断）。理由: `lastHomeState` を永続化すると、長時間アプリ未起動の間に jun さんが物理的に移動した場合に古い状態を信じてしまうリスクがあるため、現在位置から都度判定する方が堅牢。

### scenePhase と SLC 起床の関係

`SwiftUI.scenePhase` はアプリのフォアグラウンド状態を表すため、**バックグラウンド SLC 起床では `.active` にならない**。

S6-006 で導入した `RootView.onChange(of: scenePhase)` の `resumeTrackingAfterRelaunch()` 呼び出しは、ユーザーが明示的にアプリを開いた時にしか動作しない。SLC 起床経路では別の発火点が必要だった（→ 本チケットで `didUpdateLocations` 冒頭発火を追加）。

### 詳細は技術ノートを参照

`.scrum/notes/slc-wake-tracking-resume.md` に SLC 起床経路 / `lastHomeState` 永続化トレードオフ / scenePhase 非依存の保険ロジック設計を整理。Sprint 7 以降の SLC 周辺改修時はまずこれを参照する。
