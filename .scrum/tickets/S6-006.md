## ユーザーストーリー
ユーザー（jun さん）として、アプリをバックグラウンドにしていても、SLC（移動検知）でアプリが再起動された時に記録が破綻なく続くようにしたい。なぜなら、運転中にアプリを意識せず使えないと「常時記録」の価値が出ないから。

## 受け入れ条件

- [ ] `Services/Location/LocationService.swift` のバックグラウンド復帰経路を整理:
  - SLC で起動された時は `LocationService.startTrackingFromSLC()` を呼ぶ専用経路を用意
  - `applicationDidBecomeActive` 通知で前回の記録状態を復元（`UserDefaults` または Keychain で `wasTracking` フラグ管理）
  - 自宅滞在中は SLC 起動でも記録を再開しない（既存自宅判定ロジック維持）
- [ ] バックグラウンド復帰時に `currentDailyRecord` の整合を保つ（日付が変わっていたら新規 `DailyRecord` を生成）
- [ ] OS によりアプリが kill された後の SLC 起床から 30 秒以内に記録継続できる
- [ ] ユニットテスト: SLC 起床 → 記録再開 / 自宅滞在中の SLC 起床（再開しない）/ 日付跨ぎの復帰（新規 DailyRecord 生成）/ kill 後復帰時の状態整合 で 4 ケース以上 pass
- [ ] 実機検証は S6-008 で実施（運転中の SLC 起床テスト）

## 技術メモ

### Sprint 3 で構築済の枠組み

- `CLLocationManager.startMonitoringSignificantLocationChanges()` は Sprint 3 で実装済
- ただし「アプリが kill された後の起床経路」は検証が未済（Sprint 3 申し送り）
- Sprint 5 plan に「Sprint 3 申し送り #8: MKLocalSearch / SLC 実機検証」として残っていた項目

### Info.plist 設定（既存）

- `UIBackgroundModes` に `location` が含まれていることを確認
- `NSLocationAlwaysAndWhenInUseUsageDescription` の文言が「移動経路を記録するために常時位置情報を使用」になっていることを確認

### kill 後の状態復元

```swift
// 起床時のフラグ確認
@AppStorage("wasTracking") var wasTracking: Bool = false

// applicationDidBecomeActive で
if wasTracking {
    Task { await locationService.resumeTrackingAfterRelaunch() }
}
```

### iOS 26 / Swift 6 strict concurrency

- `LocationService` は actor のまま
- `applicationDidBecomeActive` の Notification ハンドラから actor メソッドを呼ぶ際は `Task { await ... }` で
