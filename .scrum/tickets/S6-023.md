## 根本原因（general-purpose レビューエージェントが実装ベースで確定）

### 主原因 (a): バッテリー最適化と滞留検知のロジック衝突

1. [`BatteryAdaptiveLocationPolicy.swift:55,101-110`](../../GPSLogger/Services/BatteryAdaptiveLocationPolicy.swift) が「直近 5 分の総移動 ≤ 100m」を停車判定 → `distanceFilter = 100m` に切替
2. [`LocationService.swift:686-690`](../../GPSLogger/Services/LocationService.swift) が CLLocationManager.distanceFilter にこの値を書き込み
3. → **滞留中（停車中）は GPS 配信が止まる**
4. [`StayDetector.swift:220-242`](../../GPSLogger/Services/StayDetector.swift) は「半径 100m 外への離脱」検知時のみ `.stayEnded(PinRecord)` を返す
5. お店を出て 100m 動いた瞬間にようやく次の点が来るが、`lastInsideAt` は到着直後のままで `duration ≒ 0` < `minDuration=600s` 判定 → **ピンが生成されずに anchor だけリセット**

つまり「滞留中は GPS が止まる」「離脱検知の瞬間は時系列ベースの滞留時間判定が `lastInsideAt` 更新に依存して 0 と算出される」という二重の欠陥で、**滞留 10 分 + 半径 100m の条件を満たしてもピンが永遠に生成されない**。

### 派生バグ (e): 地図タブのリアルタイム描画が更新されない

- [`MapViewModel`](../../GPSLogger/Features/Map/MapViewModel.swift) の `restoreTodayTrip()` は `didRestore` フラグで 1 回しか実行されない
- 走行中に新規ピンが SwiftData に保存されても **地図タブには反映されない**
- アプリ再起動 or 履歴タブで初めて見える状態になり、走行中の UX としてピンが「動いていない」ように見える

### テストカバレッジの穴（再発防止に必要）

- `StayDetectorTests` は 60 秒間隔で 11 点入力など **非現実的な前提**
- `LocationServiceLifecycleIntegrationTests` は `minDuration: 0` で **閾値を無効化**
- **`BatteryAdaptiveLocationPolicy` と `StayDetector` の統合テストが存在しない** → 本バグを検出できなかった構造的原因
- `MockLocationProvider` が `distanceFilter` を強制適用しないため、テストでは「filter 100m でも 1m 離れた点が届く」状況になり実機と乖離

## 修正方針（jun さん承認済: D + E 併用）

### タスク D: 滞留検知の堅牢化（B + C 併用）

#### D-B: StayDetector が anchor 中（=滞留検知中）は LocationService が `distanceFilter` を緩めない分岐を追加

- [`LocationService.swift`](../../GPSLogger/Services/LocationService.swift) の `updateBatteryPolicy()` 内で `stayDetector.isInsideAnchor`（または同等の状態）を参照
- 滞留検知中は `distanceFilter` を `kCLDistanceFilterNone` 相当 or 20m 程度に強制
- 滞留終了後は通常のバッテリー最適化に戻す
- 「anchor 中は GPS 配信を絞らない」ことで、離脱検知タイミングが late にならない / `lastInsideAt` が継続的に更新される

#### D-C: `RetroactiveStayDetector` を強化、離脱点 1 点でも時系列で `duration` 計算

- [`StayDetector.swift`](../../GPSLogger/Services/StayDetector.swift) / [`RetroactiveStayDetector`](../../GPSLogger/Services/RetroactiveStayDetector.swift) 経路
- 「anchor の `stayStartedAt` と最新点の `timestamp` の差」で `duration` を判定
- 半径外への離脱検知時、anchor → 離脱点の時間経過が `minDuration` 以上なら PinRecord を生成
- `lastInsideAt` の更新依存をなくす（時系列ベースに切替）
- 仮に D-B が機能せず GPS 配信が間引かれた場合でも、**離脱点 1 点だけで時系列ベースで滞留時間を判定できる** ようにする保険経路

### タスク E: 地図タブのリアルタイム描画更新

- [`MapViewModel`](../../GPSLogger/Features/Map/MapViewModel.swift) が `LocationService` の新規ピン発生イベント（または `currentTrip.pins` の変化）を購読
- ピンが追加されたら `viewModel.pins` を再フェッチして地図に反映
- `didRestore` フラグは「初回起動時の二重実行防止」用途に限定し、ランタイム更新時は別経路で再描画
- 走行中に新規ピンが SwiftData に保存された瞬間、地図タブを見ていれば **そのまま追加描画される** UX を担保

### テスト追加（必須）

1. **`BatteryAdaptiveLocationPolicy` と `StayDetector` の統合テスト**: Policy が `distanceFilter=100m` に上げた後でも滞留検知が成功するシナリオ
2. **本番デフォルト（600s/100m）での `LocationService` 統合テスト**: 実機と同じ閾値での End-to-End
3. **滞留中の GPS 配信欠落シナリオ**: 「到着 → 11 分間 GPS なし → 100m 離脱点 1 点」でピンが生成される（D-C の保険経路を担保）
4. **MapView リアルタイム描画**: 走行中にピンが追加されたら地図に反映される（タスク E）
5. **`MockLocationProvider` の `distanceFilter` 反映**: filter 値が大きい時は配信間隔も再現する mock 改善
