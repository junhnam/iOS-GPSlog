## ユーザーストーリー

ユーザー（jun さん）として、**iOS が「ユーザーが止まっている」と判断して位置情報配信を自動停止した場合でも、再び動き始めた時に確実に記録が再開されてほしい**。なぜなら、現行実装では iOS が `pausesLocationUpdatesAutomatically=true` で自動停止しても、`locationManagerDidPauseLocationUpdates(_:)` を実装していないため停止を検知できず、再開トリガーもないため、**ユーザーが再び動き始めても永遠に記録が止まったまま**になってしまうから。

---

## 背景（2026-05-19 QA オーケストレーター全体検証）

S6-005（バッテリー最適化）で `BatteryAdaptiveLocationPolicy` を導入した際、`pausesLocationUpdatesAutomatically=true` を設定したまま `locationManagerDidPauseLocationUpdates` / `locationManagerDidResumeLocationUpdates` の delegate を実装していなかった。

S6-017（SLC 空白ウィンドウ修正）で通常 GPS を atHome 中も維持する方針に転換した時点で、**「pause = アプリ全体の記録停止」になるリスクが構造的に新規発生** していたが、再評価されないまま放置されていた。

QA オーケストレーターの 2026-05-19 全体検証で「pause したまま resume されない経路が存在する」ことが判明 → リリースブロッカー化。

---

## 根本原因

### `pausesLocationUpdatesAutomatically=true` の挙動

[`LocationService.swift:191`](../../GPSLogger/Services/Location/LocationService.swift#L191) 付近で以下を設定:

```swift
manager.pausesLocationUpdatesAutomatically = true
```

この設定により iOS は **CMMotionActivity 等から「ユーザーは止まっている」と判断したタイミング** で位置情報配信を自動停止する。停止時に呼ばれる delegate は:

```swift
func locationManagerDidPauseLocationUpdates(_ manager: CLLocationManager)
func locationManagerDidResumeLocationUpdates(_ manager: CLLocationManager)
```

の 2 つだが、**現行 `LocationService` はどちらも実装していない**。

### 何が起きるか

| 状況 | 期待挙動 | 実際の挙動 |
|---|---|---|
| 走行中 | 通常 GPS 配信 | 通常 GPS 配信（OK） |
| 信号待ち / 長時間停車 | iOS が pause → 一時停止 | iOS が pause → **アプリは検知できない** |
| 再び走り出す | iOS が resume → 再配信 | iOS は resume を試みるが、**アプリ側で wasTracking / `isUpdating` 状態が不整合のまま** |
| 帰宅後タスクキル → 翌朝動き出し | SLC 起床 → 通常 GPS 再開 | pause 状態の遺残により、**resume の delegate が呼ばれず通常 GPS が走らない** ケースあり |

### S6-017 との関係

S6-017 で `startSignificantChangesIfHome` から SLC 開始呼び出しを削除し、atHome 中も通常 GPS を維持する設計に変更した。これにより:

- `pause=true` のままだと、自宅で長時間滞在中に iOS が pause → 自宅を出た瞬間に resume が走るはずだが delegate が無いので状態管理ができない
- 「家を出た瞬間に記録再開」の S6-017 設計が、`pause` 経路を経由した場合に成立しない可能性がある

→ **S6-017 で通常 GPS 維持に方針転換した時点で `pause` の方針を再評価すべきだった** が、見落とされていた。本チケットで決着をつける。

## 修正方針

### A: `pausesLocationUpdatesAutomatically=false` に倒す

```swift
manager.pausesLocationUpdatesAutomatically = false
```

理由:
- 本アプリは「移動経路を常に記録」がコア価値
- iOS の自動 pause は「ユーザーは止まっている」という主観的判断であり、本アプリの「移動経路を完全に記録」という要件と相性が悪い
- バッテリー懸念は S6-005 / S6-017 で導入した `distanceFilter` ベースの省電力で吸収可能（100m 以上動かないと配信されない = 実質 pause と同等）

### B: `locationManagerDidPauseLocationUpdates` / `locationManagerDidResumeLocationUpdates` の実装

仮に将来 `pause=true` に戻す可能性があるため、delegate 自体は実装しておく（防御的実装）:

```swift
extension LocationService: CLLocationManagerDelegate {
    func locationManagerDidPauseLocationUpdates(_ manager: CLLocationManager) {
        Self.logger.warning("iOS により位置情報配信が自動停止された（pause）。wasTracking は維持。")
        // wasTracking は維持（resume 時に再開する前提）
        // isUpdating フラグの扱いはアプリ側で false に倒すか維持するか方針確定が必要
    }

    func locationManagerDidResumeLocationUpdates(_ manager: CLLocationManager) {
        Self.logger.info("iOS により位置情報配信が再開された（resume）")
        // 必要なら resumeTrackingAfterRelaunch() 相当の状態復元を呼ぶ
        if wasTracking && !isUpdating {
            resumeTrackingAfterRelaunch()
        }
    }
}
```

### C: ドキュメント化

`.scrum/notes/pauses-location-updates-decision.md`（or 既存ノートに追記）で「**本アプリでは `pause=false` を採用する**」「将来再評価する場合の条件」を明示する。

## レビュー観点（dev-2 完了後 / general-purpose レビューエージェント向け）

1. **`pause=false` のバッテリー影響**
   - 移動中は CLLocationManager が常時配信 → S6-005 の動的精度切替が効くか
   - 停止中は `distanceFilter=100m`（atHome 中）/ 動的 distanceFilter が効いて配信が抑制されるか
   - 推定バッテリー消費（1 日の運転 + 自宅滞在のケース）を理論値で見積もる

2. **`pause/resume` delegate と `wasTracking` の整合**
   - `pause` 時に `wasTracking` を維持する判断の妥当性
   - `resume` 時に `resumeTrackingAfterRelaunch` を呼ぶ条件（`wasTracking=true && !isUpdating`）の網羅性
   - S6-015 の `didUpdateLocations` 冒頭の `needsResume` フラグと衝突しないか

3. **`isUpdating` フラグの一貫性**
   - `pause` 後の `isUpdating` の値（iOS 仕様）
   - `resume` 後の `isUpdating` の値
   - アプリ側で操作する必要があるか

4. **S6-017 のテストへの回帰**
   - `startSignificantChangesIfHome` で `desiredAccuracy=kCLLocationAccuracyHundredMeters` / `distanceFilter=100` を設定した後、`pause=false` が上書きされていないか
   - 既存 atHome モードのテストが pass するか

5. **将来 `pause=true` に戻す条件**
   - ドキュメント化（`.scrum/notes/`）の品質
   - 「バッテリー消費が許容範囲を超えた場合のみ pause を再検討」等の明示
