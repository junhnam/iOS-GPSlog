## ユーザーストーリー
ユーザーとして、滞留地点のピンに「どのお店だったか」が自動で表示されてほしい。なぜなら、後で履歴を見たときに地名だけでなくお店名やリンクで思い出せるからである。

## 受け入れ条件
- [ ] `Services/Place/PlaceLookupService.swift` を新規作成。入力は `(coordinate: CLLocationCoordinate2D)`、出力は `PlaceCandidate (name: String, url: URL?, address: String?)?`
- [ ] MKLocalSearch（Apple MapKit 標準。無料 / 認証不要）を使用し、半径 50m の Point of Interest を検索
- [ ] 検索結果が 0 件の場合は逆ジオコーディングで住所のみ返す
- [ ] StayDetector で PinRecord が新規作成されるタイミングで PlaceLookupService を呼び、`PinRecord.placeName` / `PinRecord.placeURL` に書き込む
- [ ] PinRecord に `placeName: String?` / `placeURL: String?` フィールドを追加（マイグレーション: 既存レコードは nil で OK）
- [ ] HistoryDetailView のピン詳細に placeName と「マップで開く」リンクを表示（あれば）
- [ ] ユニットテスト最低 4 ケース: (a) 検索成功で名前と URL、(b) 検索 0 件で住所のみ、(c) ネットワーク失敗で nil、(d) PinRecord への書き込み

## 技術メモ
- MKLocalSearch は MainActor 不要。結果は `MKLocalSearch.Response.mapItems` 配列の最上位を採用
- `placeURL` は `MKMapItem.url` をそのまま String 化
- iOS 26 SwiftData の落とし穴: PinRecord はリレーション配列を持たないので `= []` ルールには該当しない。ただし新規プロパティは Optional にして既存 DB と整合させる
- ネットワーク失敗時のフォールバック実装をテストできるよう `PlaceProviderProtocol` を導入してモック化

## 依存関係
- 前提: なし（Sprint 2 の StayDetector / PinRecord に依存）
- 後続: Sprint 4（カレンダー連携時に placeName を使う）

## 平易な補足（jun さん向け）
ピンが立った場所が「スターバックス渋谷店」などの店名で表示されるようにします。MKLocalSearch という Apple 標準機能を使うため、追加コストはかかりません。
