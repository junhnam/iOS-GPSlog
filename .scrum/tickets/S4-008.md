## ユーザーストーリー
開発者として、自宅判定の警告 HUD ロジックを HomeDetector に集約したい。なぜなら、Sprint 3 で MapView 側と HomeDetector 側に重複実装が残ってしまい、将来の自宅判定仕様変更時に 2 箇所を直す必要が生じるからである（Sprint 3 retro #4 / Agent A 観察事項）。

## 受け入れ条件
- [ ] `MapView.swift` 内に残っている「自宅滞在中なので記録停止中」HUD warning の判定ロジックを削除し、`HomeDetector.evaluate(...)` の戻り値（`.atHome` / `.away`）に統一して参照するだけにする。
- [ ] `HomeDetector` 側に必要なら `HomeDetectorBanner` 用の状態（例: `displayMessage`）を追加し、MapView は `HomeDetector.shared` または DI されたインスタンスから値を読むだけにする。
- [ ] 重複実装の削除前後で挙動差分なし（既存 HomeDetectorTests 9 ケース + RootViewIntegrationTests 4 ケースが回帰なし）。
- [ ] ユニットテスト 1 ケース追加: HUD メッセージが `HomeDetector` から取得されることを検証（MapView を直接テストしない代わりに HomeDetector 側の View Model 的な戻り値を確認）。
- [ ] フル再ビルドで warning 0 を維持。

## 技術メモ
- Sprint 3 の Agent A レビューで「MapView 内に `if locationService.isAtHome { showHUD = ... }` のような分岐があり、HomeDetector の判定とは独立に書かれている」と指摘されている部分が対象。実装を 1 箇所に集約。
- `HomeDetector` は純粋関数として設計されているため、ステートを持たせる場合は別の `HomeStateObservable`（@Observable）クラスを薄く作るか、LocationService が公開している `@Published var homeState: HomeState` のような既存ストリームを使う。Dev-1 の判断で最小差分を選択。
- 別実装に置き換える際、`MapView` 側で参照していた既存プロパティ名は変えず、内部で HomeDetector の値を返すラップにする（呼び出し側を壊さない）。
- Sprint 3 retro Try「Dev フェーズ完了基準に統合経路の静的レビューを追加」を意識し、本チケットの完了報告時に「RootView → MapView → HomeDetector の流れで HUD 表示判定が 1 経路に絞られていること」を明記する。
