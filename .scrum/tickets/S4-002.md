## ユーザーストーリー
ユーザーとして、滞留地点を iOS 標準カレンダーに自動で登録したい。なぜなら、後で「いつ、どこにいたか」をカレンダー上で振り返り、他のスケジュールと一緒に見られるからである。本チケットでは権限取得とカレンダー選択の基盤を整える。

## 受け入れ条件
- [ ] `GPSLogger/Services/Calendar/CalendarSyncService.swift` を新規作成。EventKit (`EKEventStore`) のラッパーで、`@MainActor` クラスとして実装。
- [ ] `Info.plist` に `NSCalendarsFullAccessUsageDescription`（iOS 17+ の新キー）を追加。説明文は日本語で「滞留地点を自動的にカレンダーに記録するために使用します」。
- [ ] 権限取得 API: `requestFullAccessIfNeeded() async -> Bool`。許可された場合 true、拒否なら false（throw しない設計）。
- [ ] 利用可能なカレンダー一覧取得: `availableCalendars() -> [EKCalendar]`（書き込み可能 `.event` タイプのみ）。
- [ ] 選択中カレンダー識別子の永続化: `AppSettings` に `calendarIdentifier: String?` を追加（`gpslogger.settings.v1.calendarIdentifier` の UserDefaults キーで保存）。
- [ ] `CalendarProviderProtocol` を導入してテスト時にモック差し替え可能にする（`Sendable`）。
- [ ] ユニットテスト最低 4 ケース: (a) 権限許可ケース、(b) 拒否ケース、(c) calendar 一覧フィルタ（`.event` のみ）、(d) AppSettings に identifier が永続化される。

## 技術メモ
- iOS 17 以降は `requestFullAccessToEvents` が必要（旧 `requestAccess(to: .event)` は deprecated）。
- `EKEventStore` のインスタンスは EventKit の推奨に従いアプリ全体で 1 つに集約。`CalendarSyncService` は `EKEventStore` を初期化時に注入できる設計にして、テスト時はフェイクを差し込む。
- 選択中カレンダー識別子は EventKit の `EKCalendar.calendarIdentifier`（不変文字列）。`AppSettings` の名前空間 `gpslogger.settings.v1.*` に追加し、Sprint 3 で確立した永続化パターンに揃える。
- 設定 UI（カレンダー選択リスト）は S4-004 で実装。本チケットは API レイヤと AppSettings 拡張のみ。
- iOS 26 SwiftData 落とし穴ノートには関係しないが、`AppSettings` を編集する際は既存の AppSettingsTests 8 ケースを壊さないこと。
