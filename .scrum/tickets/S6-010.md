## ユーザーストーリー

ユーザー（jun さん）として、運転 → 飲食店に 1 時間滞在 → 帰宅、というよくある使い方をしたとき、アプリをバックグラウンドに置いていても・OS にタスクキルされていても、その滞在場所が必ずピンとして履歴に残るようにしたい。なぜなら、CLAUDE.md の核要件「10 分以上同じ位置に立ち止まれば自動でピンを差す」が個人利用版の唯一無二のキラー機能であり、これが動かないと「経路だけ取れる地味なロガー」に成り下がるから。

---

## 背景（バグ報告 / 2026-05-09）

jun さんが iPhone 16 Pro 実機検証中に発見した致命バグ。

- 喫茶店に約 1 時間滞在（アプリはバックグラウンド + おそらくタスクキル）
- 移動軌跡（地図上の polyline）はちゃんと描かれていた
- 帰宅後にピン履歴を確認 → **0 件のまま**
- CLAUDE.md 要件「10 分以上同じ位置に留まればピン化」が満たされていない

### 原因仮説 1: iOS の自動停止

- `LocationService.configureManager()`（`LocationService.swift:183`）で `pausesLocationUpdatesAutomatically = true` 設定
- ユーザーが静止すると iOS が位置更新を勝手に停止する
- → 滞留中に位置情報イベントが来ない → `stayDetector.ingest()` が呼ばれない → 滞留判定が動かない

### 原因仮説 2: StayDetector の状態がメモリ上のみ

- `StayDetector.swift:66-72` の `anchorLocation` / `stayStartedAt` / `lastInsideAt` はメモリのみ
- タスクキルで全部消える
- 移動再開時に SLC でアプリ起動しても、StayDetector はゼロから始まる
- → 「直前にここに 10 分以上いた」記憶がない → ピン作成されない

C 案（`pausesLocationUpdatesAutomatically=false`）は CLAUDE.md のバッテリー懸念から不採用（jun さん判断 / 2026-05-09）。

### B 案（本命 / RoutePoint 後追い検知）

- [ ] 新規ファイル `Services/Trip/RetroactiveStayDetector.swift` を追加
  - 役割: 任意の `[RoutePoint]`（時系列ソート済み）を受け取り、滞留候補を検出して `[PinRecord]` を返す純粋関数的サービス
  - 入力: `RoutePoint` 配列 + `StayDetectionConfig`（既存構造体を再利用 / `radius=30m / minDuration=600s` デフォルト）
  - 出力: `[PinRecord]`（既存 `PinRecord` 型をそのまま返す。trip 紐付けは呼び出し側で行う）
  - 判定ロジック:
    - 連続する 2 点 `t1, t2` について `distance(t1, t2) <= radius` かつ `t2.timestamp - t1.timestamp >= minDuration` なら **その間に静止していた**と推定し、中心点（t1, t2 の平均座標 or t1 座標）を anchor として PinRecord を生成
    - もしくは、近接窓判定: 連続する点群でアンカーから `radius` 以内に居続け、最後の点と最初の点の時刻差が `minDuration` 以上なら滞留として確定

  - 既に保存済みの `PinRecord` と座標 +時刻が重複しないものだけ `appendPin` で永続化

## 技術メモ

### 既存実装の前提

- `StayDetector`（`GPSLogger/Services/Trip/StayDetector.swift`）: アンカー方式・半径 30m / 最小 600 秒
- `RoutePoint`（`GPSLogger/Models/RoutePoint.swift`）: `latitude / longitude / timestamp / trip` のシンプル `@Model`
- `PinRecord`（`GPSLogger/Models/PinRecord.swift`）: `latitude / longitude / stayedFrom / stayedDurationSeconds / placeName? / placeURL? / address? / calendarEventIdentifier?`
- `TripRepository.appendPin(_:to:)` で TripRecord に紐付け永続化
- `LocationService.resumeTrackingAfterRelaunch()`（`LocationService.swift:327`）が S6-006 で既に整備済み（自宅判定・日付またぎ対応済）→ ここに RetroactiveStayDetector の発火を組み込むのが最小侵襲

### iOS 26 / SwiftData 落とし穴回避

- A 案で StayDetector 状態を **SwiftData の @Model にしない**（`ios26-swiftdata.md` の落とし穴回避 / `AppSettings.wasTracking` と同じ UserDefaults 方式に統一）
- B 案は既存 RoutePoint を**読むだけ**なので新規 `@Model` 追加なし

### 後追い判定アルゴリズム（B 案）の最小実装

```swift
// 疑似コード
func detectStays(from points: [RoutePoint], config: StayDetectionConfig) -> [PinRecord] {
    var pins: [PinRecord] = []
    var anchorIndex = 0
    var i = 1
    while i < points.count {
        let anchor = points[anchorIndex]
        let cur = points[i]
        let distance = haversine(anchor, cur)
        if distance <= config.radiusMeters {
            // 半径内に居続けている
            i += 1
        } else {
            // 半径外に出た
            let lastInside = points[i - 1]
            let duration = lastInside.timestamp.timeIntervalSince(anchor.timestamp)
            if duration >= config.minDuration {
                pins.append(PinRecord(
                    latitude: anchor.latitude,
                    longitude: anchor.longitude,
                    stayedFrom: anchor.timestamp,
                    stayedDurationSeconds: duration
                ))
            }
            anchorIndex = i
            i += 1
        }
    }
    // ループ末尾の残り（最後まで半径内に居続けたケース）
    if anchorIndex < points.count - 1 {
        let anchor = points[anchorIndex]
        let last = points[points.count - 1]
        let duration = last.timestamp.timeIntervalSince(anchor.timestamp)
        if duration >= config.minDuration {
            pins.append(PinRecord(
                latitude: anchor.latitude,
                longitude: anchor.longitude,
                stayedFrom: anchor.timestamp,
                stayedDurationSeconds: duration
            ))
        }
    }
    return pins
}
```

### 冪等性の実装ヒント

`TripRepository` に `existingPins(near coordinate:, around timestamp:, within radiusMeters:, withinSeconds:) -> [PinRecord]` を追加し、新規候補ごとに既存ピンと衝突しないか確認する。

### `CLLocationManagerDelegate` の SLC 復帰経路

S6-006 で既に `startTrackingFromSLC()` / `resumeTrackingAfterRelaunch()` の枠組みあり。本チケットでは `resumeTrackingAfterRelaunch()` の最後に `runRetroactiveStayDetectionIfNeeded()` を 1 行追加する形を想定。
