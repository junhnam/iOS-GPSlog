## タスク A: iOS 26 deprecated 対応（M / 半日想定）

### 問題

`UIApplication.LaunchOptionsKey.location` が **iOS 26.0 で deprecated**。現状の回避策では:

[`GPSLogger/App/AppDelegate.swift`](../../GPSLogger/App/AppDelegate.swift) で raw value 直接使用:

```swift
let locationKey = UIApplication.LaunchOptionsKey(rawValue: "UIApplicationLaunchOptionsLocationKey")
```

この経路は警告を抑止しているだけで、**iOS が API を削除した時点でタスクキル後の SLC 起床経路（S6-018 で確立した DI 確実化 + AppDelegate.didFinish 検知）が動かなくなる時限爆弾**。リリース後に iOS のメジャー更新で破壊される前に、Apple 公式推奨の Scene ベース検出経路へ移行する。

### 修正方針

**scene connection 経由の検出に正式移行する**。

1. SwiftUI App では `UISceneDelegate` の `scene(_:willConnectTo:options:)` から `UIScene.ConnectionOptions` 経由で SLC 起床（および通常起動）を検出する
2. 現在の `AppDelegate.application(_:didFinishLaunchingWithOptions:)` 経由の SLC 検出ロジック（`launchOptions[.location]` の raw value 経路）を、scene 経路に移し替える
3. `AppDelegate` 自体は DI 初期化（S6-018 で確立した `AppDependencyContainer` 生成 + `pausesLocationUpdatesAutomatically=false` の方針）のために **残す**
   - `application(_:configurationForConnecting:options:)` で `UISceneConfiguration` を返し、その `delegateClass` に `SceneDelegate` を指定する

### 該当ファイル

- `GPSLogger/App/AppDelegate.swift`（既存修正 / `launchOptions[.location]` 検知ロジックを SceneDelegate へ移管）
- `GPSLogger/App/GPSLoggerApp.swift`（既存修正 / 必要なら `@UIApplicationDelegateAdaptor` の維持 + Scene 経路の宣言）
- `GPSLogger/App/SceneDelegate.swift`（**新規作成検討**）
- `GPSLogger/Resources/Info.plist`（`UIApplicationSceneManifest` 設定確認 / `UISceneDelegateClassName` の指定）

### 副作用注意点（必ず確認）

- **S6-018 で確立した「DI 確実化」が壊れないこと**
  - `App.init()` での `AppDependencyContainer` 生成は維持
  - `AppDelegate.application(_:didFinishLaunchingWithOptions:)` の DI 経路も維持
  - `@ObservedObject` 化された DI 参照経路も維持
- **AppDelegate と SceneDelegate の役割分担を明確に**
  - AppDelegate: プロセスライフサイクル / DI / `pausesLocationUpdatesAutomatically=false` の delegate 設定 / `application(_:configurationForConnecting:options:)` で SceneConfiguration 返却
  - SceneDelegate: scene の接続 / SLC 起床検出（旧 `launchOptions[.location]` 経路の代替） / `UISceneConnectionOptions` 経由のローンチ理由判定
- **既存 11 件のライフサイクル統合テストが pass し続けること**
  - `AppDelegateInitializationTests`（S6-020 で追加 / 4 件）
  - `LocationServiceLifecycleIntegrationTests`（S6-020 で追加 / 7 件）
  - 必要に応じて SceneDelegate 用のテストを追加（後述 受け入れ条件）

## タスク B: P7 軽微バグ修正（S / 半日以内）

### 問題

QA レポート P7（[`.scrum/notes/qa-review-2026-05-19.md`](../notes/qa-review-2026-05-19.md)）:

`HomeRegistrationView` の `.sheet` を **2 回目以降に開いた時**、`settings.homeLocation` の最新値が反映されない可能性がある。

S6-014 で `didLoadFromSettings` ガードを入れたことで「初回ロード時に外部値で `@State` を上書きしないアンチパターン」は解消したが、**シート再表示時に同じ View インスタンスが再利用されると `didLoadFromSettings == true` のままガードが効いた状態で残り、新しい設定値が onAppear で適用されない** ケースが残存する。

### 修正方針

以下のいずれかを選択（dev-2 判断 / シンプルさ優先）:

**オプション 1: シート提示方式を `.sheet(item:)` に統一**
- `SettingsView.swift` のシート提示が現在 `.sheet(isPresented:)` ベースなら、`.sheet(item: $selectedItem)` ベースに切り替えて、シートが閉じた時点で View インスタンスが破棄される設計に統一
- メリット: 構造的に再利用の問題を解消
- デメリット: SettingsView 側の State 管理が変わる

**オプション 2: `.onDisappear` で `didLoadFromSettings` をリセット**
- `HomeRegistrationView` 側で `.onDisappear` 時に `didLoadFromSettings = false` を実行
- 次回 `.onAppear` で最新の `settings.homeLocation` で再ロードされる
- メリット: 局所修正で済む / SettingsView を触らない
- デメリット: `.onDisappear` の落とし穴（`.scrum/notes/swiftui-ondisappear-pitfall.md`）を踏まないか要確認
  - 注意: `.sheet` の onDisappear は、シート閉じ時のみ発火し、タブ切替では発火しないため、`MapView` の S6-016 ケースとは異なる経路。安全と判断できる場合はこちらでもよい

### 該当ファイル

- `GPSLogger/Features/Settings/HomeRegistrationView.swift`
- `GPSLogger/Features/Settings/SettingsView.swift`（オプション 1 の場合）

## 既知の落とし穴（再発防止 / dev-2 への必読項目）

### 1. Info.plist 巻き戻し（過去 2 回事故 / S6-016 / S6-017）

dev エージェント実行時に [`GPSLogger/Resources/Info.plist`](../../GPSLogger/Resources/Info.plist) が **PLACEHOLDER** に巻き戻った事故が S6-016 / S6-017 の 2 回発生。dev-2 はコミット前に必ず:

```bash
git diff GPSLogger/Resources/Info.plist
```

を実行し、`GIDClientID` の値が `650151573001-vou0233gpmu71si47gecosirovtm2ivt.apps.googleusercontent.com` のまま残っているかを確認すること。**消えていたら即 `git checkout HEAD -- GPSLogger/Resources/Info.plist` で revert** し、別途必要な変更（`UIApplicationSceneManifest` 等）を改めて適用する。

### 2. SwiftUI `@State` init アンチパターン（S6-014 / `.scrum/notes/swiftui-state-init-pitfall.md`）

`@State` を `init` 内で `State(initialValue: 外部値)` で初期化すると、親 View の再描画で initialValue が再適用されユーザー入力が失われる。**`@State` はリテラル既定値で宣言 + `.onAppear` 内で初回ガード付き復元** が正しい形。S6-014 で `HomeRegistrationView` は既に修正済だが、タスク B の修正でも踏まないように。

### 3. SwiftUI `.onDisappear` のタブ切替発火（S6-016 / `.scrum/notes/swiftui-ondisappear-pitfall.md`）

`.onDisappear` はタブ切替でも発火する。**長寿命サービスの停止には使わない**。タスク B のオプション 2 で `.onDisappear` に `didLoadFromSettings = false` を仕込む場合、シートの `.onDisappear` は安全（タブではなくシート閉じのみ発火）なことを確認した上で使う。MapView の経路とは別物だが、念のため `MapView.swift` の `.onDisappear` ブロック削除（S6-016）を維持する。

### 4. iOS 26 SwiftData / Swift 6 落とし穴メモ（`.scrum/notes/ios26-swiftdata.md`）

新規 `@Model` を触らないチケットなので関連は薄いが、SceneDelegate 経由で DI を再構成する際、`AppDependencyContainer` から渡される `modelContainer` への参照経路が壊れないかを必ず確認。

### 5. SwiftUI App ライフサイクル × CLLocationManager（`.scrum/notes/qa-review-2026-05-19.md`）

S6-018 / S6-019 / S6-020 で確立した「`@UIApplicationDelegateAdaptor` 経由の DI + `pausesLocationUpdatesAutomatically=false` + delegate 実装 + ライフサイクル統合テスト 11 件」の仕組みを **絶対に壊さない**。SceneDelegate 移行はこの仕組みの上に乗せる形（AppDelegate を残しつつ SceneDelegate を追加）が安全。
