## ユーザーストーリー
ユーザー（jun さん）として、アプリ内に設定画面を持ち、自宅・記録モードなどのオプションを変更できるようにしたい。なぜなら、生活環境や利用シーンに応じて挙動を切り替えたいからである。

## 受け入れ条件
- [ ] タブバーまたはナビゲーションから「設定」画面に遷移できる（既存 `GPSLogger/Features/Settings/` を起点に SettingsView.swift を新規作成）
- [ ] 設定画面が SwiftUI の `Form` または `List` で実装されており、以下のセクションが存在する（中身は後続チケットで埋める）
  - 「自宅」セクション（S3-002 / S3-003 で詳細化）
  - 「記録モード」セクション（S3-004 / S3-005 で詳細化）
- [ ] `AppSettings` 観測可能オブジェクト（`@Observable` クラス）を新規作成し、UserDefaults との read/write を 1 箇所に集約
- [ ] 保持する設定値: `recordingMode: RecordingMode (.continuous / .trigger)`、`homeLocation: HomeLocation?`、`homeRadiusMeters: Double = 100`
- [ ] アプリ再起動後も設定値が保持されること（UserDefaults キーは `gpslogger.settings.v1.*` で名前空間化）
- [ ] ユニットテスト: `AppSettings` の読み書き往復、デフォルト値、不正データ時のフォールバックを最低 3 ケース

## 技術メモ
- 既存 `GPSLogger/Features/Settings/` は空ディレクトリ。`SettingsView.swift` `AppSettings.swift` を新規作成
- `AppSettings` は `@MainActor @Observable final class`。`HomeLocation` は `Codable` struct（緯度・経度・住所）として `Models/` 配下に置く
- UserDefaults へは `JSONEncoder` で Codable をシリアライズして保存（後で SwiftData 移行する場合のため疎結合に）
- iOS 26 SwiftData の落とし穴: 設定は SwiftData ではなく UserDefaults に置くのでクラッシュ条件には該当しないが、後続チケットで SwiftData の `HomeLocation` モデルを作る場合は `@Relationship` 配列 = [] ルールに注意（S3-010 で notes 化済）

## 依存関係
- 前提: なし（Sprint 2 の成果物に依存しない独立タスク）
- 後続: S3-002（自宅登録 UI）、S3-004（記録モード切替）

## 平易な補足（jun さん向け）
これは「設定画面の入れ物」を作るチケットです。中身（自宅登録ボタン、記録モード選択）は別チケットで埋めていきます。アプリを閉じても設定が残るように UserDefaults という iOS 標準の保存場所を使います。
