## ユーザーストーリー

ユーザー（jun さん）として、**自宅登録画面でピン位置・半径・住所を編集して「保存」ボタンを押したら、その内容がそのまま AppSettings に保存されてほしい**。なぜなら、自宅設定は「自宅で停滞している場合は記録を中止」「自宅を離れたら記録を開始」という常時同期モードの中核ロジックを左右する設定であり、ユーザーが指定した位置と異なる位置（保存前の値 / 東京駅）が保存されると、自宅判定が完全に誤動作するから。

---

## 背景（実機検証 3 回目フィードバック / 2026-05-09 22:30 頃）

S6-013 完了後、jun さんが iPhone 16 Pro 実機で再々検証した際に発見した自宅設定の致命バグ:

### バグ1: 自宅でピン位置を修正して保存しても、保存前の値に戻る

- 既に登録済みの自宅を開いて地図上でドラッグ → 別の場所を指定 → 「保存」ボタン押下
- 期待: 新しい位置が AppSettings に保存される
- 実際: 保存後にシートを再表示すると、保存前の元の位置に戻っている（保存が反映されていない）

### バグ2: 自宅を一度削除して再登録すると、地図上では修正できるが保存すると東京駅で固定される

- 自宅を削除 → 再登録ボタンで自宅登録画面を開く
- 地図を任意の位置にドラッグ → 「保存」ボタン押下
- 期待: ドラッグ後の位置が AppSettings に保存される
- 実際: AppSettings には `defaultCenter`（東京駅）の座標が保存される

### 根本原因

`HomeRegistrationView` の `@State` を `init` 内で外部値（`settings.homeLocation`）から `State(initialValue:)` で初期化していた。

```swift
// 修正前（バグの原因）
init(settings: AppSettings, onDismiss: @escaping () -> Void) {
    self.settings = settings
    self.onDismiss = onDismiss
    if let existing = settings.homeLocation {
        _selectedCoordinate = State(initialValue: existing.coordinate)
        _selectedAddress = State(initialValue: existing.address)
    }
    _radius = State(initialValue: settings.homeRadiusMeters)
}
```

`save()` で `settings.homeLocation` を書いた瞬間に `@Bindable` 経由で親 `SettingsView` が再描画され、sheet content closure 経由で `HomeRegistrationView` の `init` が再評価される。SwiftUI の挙動として、特定のタイミングで `initialValue` が再適用され、ユーザー入力値（`selectedCoordinate` / `radius` / `selectedAddress`）が「保存前の元値」または「東京駅の `defaultCenter`」に戻ってしまっていた。

これは SwiftUI 全般の既知アンチパターンで、`@State` の初期値は宣言時のリテラルで固定し、外部値の取り込みは `.onAppear` 等で副作用として行うのが正しい流儀。

## 技術メモ

### SwiftUI の `@State` を `init` で外部値から初期化するアンチパターン

`@State` は View の identity に紐づく永続ストレージで、**View の再生成時に初期値が再適用される条件**が SwiftUI 内部で発生する。特に:

- 親 View が `@Bindable` / `@ObservedObject` 経由で再描画される
- sheet content closure が再評価される
- View の identity が（外見上同じでも）内部的に切り替わる

これらのケースで、`init` 内で `State(initialValue: 外部値)` 形式で初期化していると、ユーザー入力で更新された State が「外部値の現在値」または「初期値」に戻されてしまう事故が起きる。

**正しい流儀**:
1. `@State` は宣言時のリテラル定数で初期化する
2. 外部値の取り込みが必要な場合は `.onAppear` / `.task` 内で副作用として実施し、初回ガード（`didLoad` フラグ）を付ける
3. もし外部値の変化を継続的に追従したいなら `.onChange(of:)` を使う

このアンチパターンは Sprint 7 以降の他画面でも踏みうるため、`.scrum/notes/swiftui-state-init-pitfall.md` に技術メモとして残した（再発防止）。
