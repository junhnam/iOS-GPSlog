## ユーザーストーリー
ユーザー（jun）として、アプリを一度閉じても、再起動したときに「今日のここまでの経路・ピン・総移動距離」が地図上に再表示されるようにしたい。なぜなら長距離移動の途中でアプリを閉じても、続きから記録できるという安心感を持ちたいから。

## 受け入れ条件
- [ ] `GPSLogger/Features/Map/MapViewModel.swift`（または同等の VM/Coordinator）を新規/拡張し、起動時に以下を行う
  - `TripRepository.todayTrip(creatingIfMissing: false)` で当日の TripRecord を取得
  - 取得できた場合: `routePoints` を `CLLocation` 配列へ変換して `MapView` の polyline に再描画させる
  - 取得できた場合: `pins` を地図上に再描画する（`GMSMarker` を1ピンずつ配置、タイトルは「滞留 約{n}分」）
  - 取得できた場合: 画面上部または HUD 領域に「総移動距離: X.XX km」を表示する
  - 取得できなかった場合（初回 / 当日まだ走っていない）: 何も復元せず通常起動
- [ ] 復元後、新規座標が来たときに polyline が正しく続きから伸びる（差分 append が壊れない）
- [ ] 既存ピン位置に戻った場合でも、復元済みピンは重複再生成しない（座標 + stayedFrom で重複判定）
- [ ] 起動から地図表示までの体感遅延が 1 秒以内（30 日分の RoutePoint を超えるような巨大データは fetch を当日分のみに限定する）
- [ ] `GPSLoggerTests/TripRestoreTests.swift`（または既存テストへの追加）で以下を検証
  - 事前にインメモリリポジトリに TripRecord（RoutePoint x 5, PinRecord x 1, totalDistanceMeters = 1234）を投入
  - VM/Coordinator の `restoreTodayTrip()` 呼び出し後、`route.count == 5`、`pins.count == 1`、`totalDistanceKm == 1.23` が一致

## 技術メモ
- データ層は S2-001〜S2-003 で完成済み前提。本チケットは「読み取って地図に流し込む」表示層と接続層が中心
- polyline の差分描画は Sprint 1 で `Coordinator.applyRoute` を実装済み。復元時は一括投入 → 以降は差分 append
- ピンの種類分け（自宅 / その他）は Sprint 3 で扱うため、本チケットでは全ピン同色でOK
- 総移動距離の表示位置は Designer の S1-008 モックを尊重しつつ、本チケットでは最低限「地図上の HUD ラベル」or「ナビゲーションバータイトル」のいずれか1箇所で可
- 起動時の SwiftData fetch はメインスレッドで OK（@MainActor 前提、データ量も当日分のみで限定的）

## 依存関係
- 前提: S2-001（モデル）、S2-002（Container）、S2-003（リポジトリ）、S2-005（保存形式が固まっていること）
- 後続: S2-008（履歴タブの詳細画面で同じ復元ロジックを部分流用）
