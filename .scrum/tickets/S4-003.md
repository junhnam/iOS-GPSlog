## ユーザーストーリー
ユーザーとして、滞留ピンが立った時にカレンダーへ自動でイベントが追加されてほしい。なぜなら、出かけ先での滞在を後から手動入力せずに振り返れるからである。

## 受け入れ条件
- [ ] `CalendarSyncService` に `createEvent(for pin: PinRecord) async -> Result<String, CalendarSyncError>` を追加。成功時に `EKEvent.eventIdentifier` を返す。
- [ ] イベントタイトル: `placeName` があれば `placeName`、無ければ `address`、両方無ければ `"滞留地点 (緯度.., 経度..)"` の順でフォールバック。
- [ ] イベント開始時刻: PinRecord の `arrivedAt`（滞留開始時刻）／ 終了時刻: `leftAt`（滞留終了時刻、未確定なら `arrivedAt + 10 分`）。
- [ ] イベントの場所: `placeName` または `address` を `EKEvent.location` に詰める。座標は `EKStructuredLocation` で `geoLocation` を入れる（Apple 推奨）。
- [ ] イベント作成は `AppSettings.calendarSyncEnabled` が true の場合のみ実行。false なら no-op。
- [ ] 重複防止: `PinRecord` に `calendarEventIdentifier: String?` を追加（マイグレーション: 既存レコード nil で OK、SwiftData の Optional 互換）。同一 PinRecord に対して 2 回目以降は再作成しない。
- [ ] エラーハンドリング: 権限拒否 / 保存失敗 / カレンダー未選択 を `CalendarSyncError` 列挙型で表現し、ログに残すが UI を停止しない（バックグラウンド処理）。
- [ ] ユニットテスト最低 5 ケース: (a) placeName ありで作成成功、(b) placeName なし → address fallback、(c) 同期 OFF で no-op、(d) 重複呼び出しで 2 回作成されない、(e) 権限拒否で `.permissionDenied` を返す。

## 技術メモ
- StayDetector が PinRecord を新規作成 → PlaceLookupService（S3-007）で `placeName` を埋める → そのタイミングで `CalendarSyncService.createEvent` を呼ぶ流れ。LocationService の既存フローに 1 行追加する形で接続する。
- `EKEvent` 作成時の `calendar` には AppSettings の `calendarIdentifier` から `EKEventStore.calendar(withIdentifier:)` で取得したものをセット。識別子が無効になった場合は `.calendarNotFound` エラーを返す。
- iOS 26 SwiftData ノート（.scrum/notes/ios26-swiftdata.md）の落とし穴 #5 に従い、新規プロパティ `calendarEventIdentifier` は **必ず Optional** にして既存 DB と互換を取る。
- 重複防止は `PinRecord.calendarEventIdentifier != nil` を見るだけで十分（識別子があれば既に作成済み）。
- カレンダーへの書き込みは `EKEvent.span = .thisEvent` + `commit:` で永続化する。

## 平易な補足（jun さん向け）
お店や施設に 10 分以上滞留したとき、iOS のカレンダーアプリにその予定が自動で記録されます。タイトルは「スターバックス渋谷店」のようにお店名が入り、開始 / 終了時刻もちゃんと記録されます。同じピンに対して 2 回作られないように、PinRecord にカレンダーのイベント ID を覚えておく仕組みも入れます。
