## 技術メモ

### SDK 比較（Dev-2 が実装着手時に確定する）

| 候補 | メリット | デメリット |
|---|---|---|
| `GoogleSignIn-iOS` + `google-api-objectivec-client-for-rest` | 公式 SDK で OAuth フローが安定 | バイナリサイズ +10〜15MB 程度。Objective-C ベースで Swift bridging のコード量増 |
| `URLSession` + Drive REST v3 を直接 | 依存ゼロ、バイナリサイズ増なし | OAuth フロー実装の自前負担。トークンリフレッシュ・PKCE などの仕様を自前で踏む |

実装着手前に Dev-2 が PO/SM へ「どちらで実装するか」の判断を仰ぐ。Sprint 5 のチケット粒度は L 想定だが、SDK 採用なら大半が SDK の API 呼び出しコードで M 〜 L 寄り、自前 URLSession なら自前実装の比率が増えて L 寄りになる。

### iOS 26 / Swift 6 strict concurrency

- `GoogleDriveSyncService` は `@MainActor` ではなく、actor または `Sendable` 構造体ベースで実装する（バックグラウンド I/O が前提のため）
- `GoogleDriveAccount` / `GoogleDriveFile` は `Sendable` 準拠

### 機密情報の扱い

- OAuth クライアント ID（iOS 用）は機密情報ではない（公開しても問題ない、Apple App Transport Security の枠組みでバンドル ID と紐付くため）
- OAuth クライアントシークレットはモバイル iOS では発行されない（PKCE フローを使う）
- アクセストークン / リフレッシュトークンは Keychain に保存（UserDefaults や AppSettings の plist には書き込まない）

### 後続チケットとの関係

- S5-003（クラウド保存先選択 UI）から `GoogleDriveSyncService.authenticate()` を呼ぶ
- S5-005（自動アップロード）から `uploadCSV(...)` を呼ぶ
- S5-006（リトライ + 通知）が `GoogleDriveSyncError` をハンドル
