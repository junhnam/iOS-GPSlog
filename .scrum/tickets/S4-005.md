## ユーザーストーリー
ユーザーとして、移動記録を CSV ファイルとして手元に持ち出したい。なぜなら、スプレッドシートで分析したり、別のサービスに取り込んだり、バックアップとして保管したいからである。

## 受け入れ条件
- [ ] `GPSLogger/Services/Export/CSVExportService.swift` を新規作成。`@MainActor` クラス（SwiftData の `ModelContext` を扱うため）。
- [ ] エクスポートメソッド: `exportTripRecord(_ trip: TripRecord) -> URL`（一時ファイル `FileManager.default.temporaryDirectory` に書き出し、その URL を返す）。
- [ ] CSV スキーマは CLAUDE.md の DB テーブル定義そのまま:
  - メタデータ行: `date, totalDistanceKm, startedAt, endedAt`
  - 経路セクション: `routePoints` を `timestamp, latitude, longitude, accuracy` で列挙
  - ピンセクション: `pins` を `arrivedAt, leftAt, latitude, longitude, placeName, placeURL, address` で列挙
- [ ] 文字エンコーディングは **UTF-8 BOM 付き**（Excel で文字化けしないため）。
- [ ] CSV インジェクション対策: 値が `=`, `+`, `-`, `@` で始まる場合は先頭にシングルクォート `'` を付与。
- [ ] 全期間エクスポートメソッド: `exportAllTrips() -> URL`（`gpslog_export_<日付>.csv` として全 TripRecord を 1 ファイルに連結）。
- [ ] ユニットテスト最低 5 ケース: (a) 単一 trip の出力スキーマ、(b) BOM 付き UTF-8 が先頭にある、(c) ピンの placeName に `,` `\n` `"` が含まれてもエスケープ、(d) CSV インジェクション対策が効く、(e) routePoints / pins が空でもメタデータ行は出力される。

## 技術メモ
- CSV エスケープ: 値内のダブルクォートは `""` で 2 重化、値内に `,` `\n` `"` のいずれかが含まれる場合は値全体をダブルクォートで囲む（RFC 4180 準拠）。
- 改行コードは `\r\n`（CRLF）で固定（Excel 互換）。
- 一時ファイル URL は呼び出し側（S4-006 / S4-007）が UIDocumentPickerViewController に渡して、jun さんが保存先を選ぶ。サービス側は永続化先を意識しない。
- `CSVExportProviderProtocol` を導入してテスト容易性を確保（実 ModelContext を必要としないインタフェース）。
- 大量レコードの場合は `String` 連結ではなく `OutputStream` で書き出す（メモリ消費を抑える）。Sprint 4 の MVP では数百件規模を想定し String で十分だが、コメントで Sprint 6 の最適化候補と記録する。

## 依存関係
- 前提: なし（独立で着手可能）
- 後続: S4-006（保存先選択）/ S4-007（UI から呼び出し）

## 平易な補足（jun さん向け）
DB に保存している記録（日付・移動経路・ピン・総移動距離など）を、Excel で開ける CSV ファイルにまとめます。日本語のお店名が文字化けしないように UTF-8 BOM という指示を先頭に付けます。CSV を出すだけで、保存先（iCloud Drive など）の選択は次のチケット（S4-006）で扱います。
