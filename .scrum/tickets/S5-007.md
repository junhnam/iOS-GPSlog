## ユーザーストーリー
（開発者ストーリー）次に PinRecord 周りを触る Dev として、「addressFromPlaceURL の実装が `pin.placeName` を返すだけで no-op」という dead code を解消し、PinRecord に `address` フィールドを追加して、StayDetector / PlaceLookup の流れで address を保存できるようにしたい。なぜなら、jun さんから「address フィールドを追加できるのであればそうした方が良い」と明示指示されたため、また CalendarSyncService の S4-003 受け入れ条件「placeName → address → 座標」の 3 段フォールバックが文言通りに動くようにしたいから。

## 受け入れ条件

- [ ] `Models/PinRecord.swift` に `var address: String?` を追加（Optional・既定 nil。iOS 26 SwiftData ノート #5 「新規プロパティは Optional で既存 DB と互換」に従う）
- [ ] `PinRecord.init(...)` の引数末尾（`trip:` の前）に `address: String? = nil` を追加（既存呼び出しに影響なし）
- [ ] `Services/Place/PlaceLookupService.swift`:
  - `PlaceCandidate.address` は既に存在するので、それを `PinRecord.address` に書き戻す経路を追加
  - 具体的には `LocationService.enrichPinWithPlaceInfo(...)` などピンに place 情報を書き込む箇所で `pin.address = candidate.address` を追加
- [ ] `Services/Calendar/CalendarSyncService.swift`:
  - `addressFromPlaceURL(_ pin: PinRecord)` を削除（dead code 解消）
  - `let location = pin.placeName ?? Self.addressFromPlaceURL(pin)` を `let location = pin.placeName ?? pin.address` に変更
  - これで「placeName → address → 座標」の 3 段フォールバックが正しく機能する（座標は別関数 `coordinateString(for:)` などで既に実装されているはず）
- [ ] ユニットテスト追加:
  - `PlaceLookupServiceTests`: address 書き戻し経路（reverseGeocode 由来 / MKLocalSearch 由来）を 2 ケース追加
  - `CalendarEventCreationTests`: placeName のみ / address のみ / placeName + address 両方 / 両方 nil（座標フォールバック）の 4 ケース追加
  - `PinRecordTests`（新規）: address 引数の有無で初期化できる、デフォルト nil の 2 ケース
- [ ] iOS 26 SwiftData マイグレーション: 既存 DB に address カラムが無くてもクラッシュしないことを確認（Optional プロパティ追加なら自動マイグレーション）

## 技術メモ

### 背景（QA-S4-002 / Sprint 4 review.md 申し送り #3）

`CalendarSyncService.swift:255-262`:
```swift
private static func addressFromPlaceURL(_ pin: PinRecord) -> String? {
    return pin.placeName
}
```
呼び出し: `let location = pin.placeName ?? Self.addressFromPlaceURL(pin)`

これは `pin.placeName ?? pin.placeName` と同じで、address の 2 段目フォールバックとしては no-op。S4-003 受け入れ条件「placeName → address → 座標」の文言に合わせるために PinRecord.address を追加して実体化する。

### jun さんの明示指示（2026-05-06）

> address フィールドを追加できるのであればそうした方が良い気がしています。

→ Sprint 5 の Must で取り込み確定。

### iOS 26 SwiftData の注意点

- 新規 Optional プロパティの追加は SwiftData の自動マイグレーションで対応可能（`.scrum/notes/ios26-swiftdata.md` の #5 ルール）
- 既存 PinRecord レコードは address = nil のまま運用される（既存ピンに address を遡及付与する処理は不要）
