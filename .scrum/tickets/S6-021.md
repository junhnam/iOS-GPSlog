## ユーザーストーリー

ユーザー（jun さん）として、**滞留検知でピンが立った場所には、後追いで取得された店舗名（placeName）が確実に DB に書き込まれてほしい**。なぜなら、後追いピン（`RetroactiveStayDetector` 経由で生成されたピン）に対して placeName の取得が走った時、ピンがまだ trip に紐付いていない瞬間に DB 保存が走ると、placeName が永遠に書かれない（ピンに「unknown」のまま残る）状態が発生してしまうから。

---

## 背景（2026-05-19 QA オーケストレーター全体検証）

QA レポートの追加バグ（P5）として発見。リリースブロッカーではないが、本 PR スコープに含めて統合 PR で同時マージする。

### 観測条件

S6-010 で導入した `RetroactiveStayDetector` は、`LocationService` の遅延発火経路を通じて「後から」ピンを `Trip` に追加する。一方、`enrichPinWithPlaceInfo`（MKLocalSearch 経由で店舗名を取得する処理）は、ピン生成と並行に走るため、**ピンが trip に紐付く前** に place 情報の取得が完了するレースコンディションが存在する。

### 該当箇所

[`GPSLogger/Services/Location/LocationService.swift:781-824`](../../GPSLogger/Services/Location/LocationService.swift#L781-L824)（`enrichPinWithPlaceInfo`）:

```swift
private func enrichPinWithPlaceInfo(pin: PinRecord) async {
    do {
        let candidate = try await placeLookupService.lookup(
            coordinate: pin.coordinate
        )
        // ← pin.trip == nil のガードが無い
        pin.placeName = candidate.name
        pin.placeURL = candidate.urlString
        try await tripRepository.save(pin: pin)  // 後追いピンが trip 未紐付けだと
                                                 // SwiftData が save 時に
                                                 // pin だけ単独で書く / 親 Trip の整合性が崩れる
    } catch {
        Self.logger.warning("placeName 取得失敗: \(error.localizedDescription)")
    }
}
```

### 何が起きるか

1. `RetroactiveStayDetector` が新しいピンを生成（`pin.trip == nil` の瞬間が存在）
2. 並行して `enrichPinWithPlaceInfo` が start（MKLocalSearch 経由 / 数秒かかる）
3. 数秒後、MKLocalSearch から店舗名取得成功
4. `pin.trip == nil` のまま `pin.placeName = candidate.name` を代入
5. `tripRepository.save(pin: pin)` 実行 → **SwiftData の `@Relationship` 整合性エラー or サイレント無視**
6. ユーザーから見ると「ピンに店舗名が永遠に表示されない」

iOS 26 SwiftData の `@Relationship` 仕様（`.scrum/notes/ios26-swiftdata.md` 参照）により、pin が trip に紐付いていない状態での save は不定挙動になりやすい。

## 修正方針

### A: ガード追加

```swift
private func enrichPinWithPlaceInfo(pin: PinRecord) async {
    do {
        let candidate = try await placeLookupService.lookup(
            coordinate: pin.coordinate
        )

        // ガード: pin が trip に紐付いていない場合は遅延 or スキップ
        guard pin.trip != nil else {
            Self.logger.warning("enrichPinWithPlaceInfo: pin が trip 未紐付け / 後追い完了待ち")
            // 数百 ms 遅延して再試行 or 永続的にスキップ（dev-2 判断）
            return
        }

        pin.placeName = candidate.name
        pin.placeURL = candidate.urlString
        try await tripRepository.save(pin: pin)
    } catch {
        Self.logger.warning("placeName 取得失敗: \(error.localizedDescription)")
    }
}
```

### B: 再試行戦略（オプション / dev-2 判断）

**オプション 1**: 即時スキップ（`return`）+ 次回の `RetroactiveStayDetector` 走査時に再度 enrichment を試みる
- メリット: シンプル
- デメリット: 再試行経路を別途用意する必要

**オプション 2**: 短い遅延後リトライ（最大 2〜3 回）
- メリット: 1 メソッド内で完結
- デメリット: 遅延量の調整が必要

**推奨**: オプション 1（シンプル）+ `RetroactiveStayDetector` 完了通知経由で enrichment を再 enqueue する設計
