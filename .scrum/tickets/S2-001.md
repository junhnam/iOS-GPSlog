## ユーザーストーリー
ユーザー（jun）として、アプリを閉じても1日分の移動データ（経路・ピン・総移動距離）が消えない構造を持っていたい。なぜなら遠出の記録を後から見返したいから。

## 受け入れ条件
- [ ] `GPSLogger/Models/TripRecord.swift` に `@Model class TripRecord` を作成
  - フィールド: `date: Date`（@Attribute(.unique)、当日の0時固定）、`startedAt: Date`、`endedAt: Date?`、`totalDistanceMeters: Double`（既定値 0）
  - リレーション: `routePoints: [RoutePoint]`（cascade delete）、`pins: [PinRecord]`（cascade delete）
  - 計算プロパティ: `totalDistanceKm: Double`（小数点第2位まで丸め、表示用）
- [ ] `GPSLogger/Models/RoutePoint.swift` に `@Model class RoutePoint` を作成
  - フィールド: `latitude: Double`、`longitude: Double`、`timestamp: Date`、`trip: TripRecord?`（逆参照）
- [ ] `GPSLogger/Models/PinRecord.swift` に `@Model class PinRecord` を作成
  - フィールド: `latitude: Double`、`longitude: Double`、`stayedFrom: Date`、`stayedDurationSeconds: Double`、`placeName: String?`（Sprint 3 で MKLocalSearch 連携、ここでは nil 許容）、`placeURL: URL?`、`trip: TripRecord?`
- [ ] 各モデルに日本語コメントで「フィールドの意味」「Sprint 何で何が追加されるか」を記載
- [ ] iOS 26+ の SwiftData マクロを使用し、`xcodebuild` でビルドが通ること（warning 0）

## 技術メモ
- 日付PKは `Calendar.current.startOfDay(for:)` で正規化した値を使う（同一日付の重複保存防止）
- リレーションは `@Relationship(deleteRule: .cascade, inverse: ...)` で双方向定義
- 距離は内部で「メートル」で持ち、表示時に km へ変換（精度ロス防止）
- お店情報（placeName/placeURL）は Sprint 3 の S3 系で MKLocalSearch 連携時に書き込む。Sprint 2 では nil でOK
- project.yml 編集時は dev-2 と競合しないよう、このチケット内で `Models/` 配下を含めるよう sources を更新
