## ユーザーストーリー

ユーザー（jun さん）として、地図上に立った滞留ピンをタップしたとき、そのピンの詳細（お店の名前 / 滞留時間 / 滞留開始時刻 / 座標）を確認でき、ワンタップで Apple Maps / Google Maps を開いて「このお店どこだっけ」をすぐ調べたい。なぜなら、CLAUDE.md 要件「ピンにはその場所のお店情報などを紐付ける」を満たすには、紐付けたデータを **ユーザーが見られる導線** が必須であり、それがないと「データはあるけど取り出せない」ロガーになってしまうから。

---

## 背景（実機検証フィードバック / 2026-05-09）

jun さんが iPhone 16 Pro 実機検証で発見した UX バグ群:

1. ピンに **店舗情報（placeName / address）が表示されない**
2. ピンタップしても **詳細表示・外部マップ起動など何も起こらない**

### コード調査済の事実（メイン代行 Explore 結果）

- `enrichPinWithPlaceInfo` は B 案後追い検知側でも呼ばれている（[`LocationService.swift:695`](../../GPSLogger/Services/Location/LocationService.swift)）
- `PlaceLookupService` は [`AppDependencyContainer.swift:80,102`](../../GPSLogger/App/AppDependencyContainer.swift) で `LocationService` に注入済み
- `PinRecord.placeName` / `placeURL` / `address` のフィールドは Sprint 3〜5 で実装済み
- → **コードパス上は enrichment は呼ばれている可能性が高い**。そのうえで「UI 上で見えていないだけ」が最有力
- `MapView.swift:254` の `Coordinator: GMSMapViewDelegate` には `mapView(_:didTap marker:)` **未実装**
- → これが「ピンタップで何も起こらない」の **直接原因**
- 既存の `marker.snippet = pin.placeName`（[`MapView.swift:307-309`](../../GPSLogger/Features/Map/MapView.swift)）は GMSMarker の標準 snippet 表示には乗っているが、jun さんの体感では「タップしても何も出ない」状態
  - 推測 1: snippet のデフォルト InfoWindow が GMSMapView 側で何らかの設定でブロックされている
  - 推測 2: そもそも placeName が nil（enrichment 失敗）で snippet が空 → Info Window が出ても情報量ゼロ
  - 本チケットでは推測のいずれであっても **明示的な詳細シートを出す方針** で UX を確実に改善する（snippet 表示に頼らない）

## 受け入れ条件

### 機能要件

- [ ] **ピンタップで詳細シート（modal sheet）を表示**
  - `MapView.Coordinator` に `mapView(_:didTap marker:) -> Bool` を実装
  - タップされた marker の userData から PinRecord を引ける状態にする（`marker.userData = pin` を `applyRestoredPinsIfNeeded` で設定 / `RestoredPin` 構造体に必要情報を全部詰める）
  - 戻り値は `true`（標準 InfoWindow を抑制してカスタムシートに統一）
  - SwiftUI 側に `@State var selectedPin: RestoredPin?` を持ち、`.sheet(item: $selectedPin)` で `PinDetailView` を表示
- [ ] **詳細シートに以下の情報を表示**
  - 店舗名（`placeName`）
    - あり: そのまま表示
    - 空: 「お店情報を取得中...」または「（取得失敗）」を明示表示（jun さんが「データがないのか取得中なのか」を識別できる）
  - 住所（`address` / S5-007 で追加済）— あれば表示、なければ非表示
  - 滞留時間（`stayedDurationSeconds` を「約 N 分」「約 N 時間 M 分」に整形）
  - 滞留開始時刻（`stayedFrom` を `DateFormatter.shortDateAndTime` 相当でローカル時刻表示）
  - 座標（`latitude, longitude` を小数点 5 桁で表示 / 開発確認用）
- [ ] **「Apple Maps で開く」ボタン**
  - URL スキーム: `http://maps.apple.com/?ll={lat},{lon}&q={placeName or 座標}`（`MKMapItem.openInMaps` でも可）
  - placeName が nil の場合は座標のみで起動
- [ ] **「Google Maps で開く」ボタン**
  - インストール済み判定: `UIApplication.shared.canOpenURL(URL("comgooglemaps://")!)`
  - インストール済み: `comgooglemaps://?q={lat},{lon}`（または `q={placeName}`）
  - 未インストール: web URL `https://www.google.com/maps/search/?api=1&query={lat},{lon}` にフォールバック
  - Info.plist の `LSApplicationQueriesSchemes` に `comgooglemaps` を追加（**追加変更が必要**）
- [ ] **「閉じる」ボタン**で sheet をディスミス
- [ ] **ピンの placeName が空 / address も空の場合**:
  - シート上部に控えめな注記「お店情報の取得に失敗しました。座標のみ表示しています。」を出す
  - Apple Maps / Google Maps 起動ボタンは使える（座標がある以上、外部マップで開ける）

### DI / 構造要件

- [ ] `MapView` から SwiftUI シートを表示する経路を確立（既存 `LocationService` / `repository` の DI に変更を加えない）
- [ ] `PinDetailView` は presentation layer のみ。ロジックは持たず、表示用 props（`PinDetailModel` 構造体）を受け取る純粋 View
- [ ] `PinDetailModel` は `RestoredPin` から生成できるファクトリ初期化を持つ
- [ ] 既存の `RestoredPin` 構造体に `placeName` / `address` / `latitude` / `longitude` / `stayedFrom` / `stayedDurationSeconds` を保持していなければ追加（既に `placeName` はあるので差分のみ）
- [ ] `MapView.makeUIView` または `applyRestoredPinsIfNeeded` で `marker.userData` に `RestoredPin` を設定
- [ ] DI カバレッジテストは新規サービスを追加しないため不要（S6-001 雛形に従い、不要である旨をコミットメッセージに明記）

### 受け入れ条件: ユニットテスト（最低 4 件）

- [ ] **T-1**: `mapView(_:didTap:)` がマーカーから `RestoredPin` を取り出して selectedPin にセットすることを確認（GMSMapViewDelegate のモック / `marker.userData` 経由）
- [ ] **T-2**: Apple Maps URL 生成（placeName あり / なし両ケース）が期待文字列を返すことを確認
- [ ] **T-3**: Google Maps URL 生成（インストール済 / 未インストール両ケース / `canOpenURL` をモック化）

GMSMapViewDelegate 自体のモックが書きづらい場合は、`Coordinator` に `handleMarkerTap(pin: RestoredPin)` のようなテスト可能な internal メソッドを抽出して、デリゲートメソッドはそこに委譲する形が望ましい（テスト容易性の観点）。

## 技術メモ

### URL スキーム仕様

| マップアプリ | URL スキーム例 | 備考 |
|---|---|---|
| Apple Maps | `http://maps.apple.com/?ll=35.681236,139.767125&q=東京駅` | Web URL でも `maps.apple.com` ドメインなら自動的に Maps.app が開く（iOS 標準）|
| Apple Maps（代替） | `MKMapItem(placemark:).openInMaps(launchOptions:)` | より明示的な Apple API。今回はどちらでも可 |
| Google Maps | `comgooglemaps://?q=35.681236,139.767125` | アプリ未インストール時は `canOpenURL` が false を返す |
| Google Maps（web フォールバック） | `https://www.google.com/maps/search/?api=1&query=35.681236,139.767125` | 未インストール時は Safari で開く |

### Info.plist 追加例

```xml
<key>LSApplicationQueriesSchemes</key>
<array>
    <string>comgooglemaps</string>
    <string>comgooglemaps-x-callback</string>
</array>
```

iOS 9+ から `canOpenURL` の対象スキームは Info.plist に明示しないと常に false。これを忘れると Google Maps インストール済でも「未インストール扱い」になる。

### enrichPinWithPlaceInfo の現状確認（dev エージェントへ）

このチケットは UI 改修が主だが、もし `placeName` が常に nil なら enrichment 自体が動いていないことになる。実装着手前に下記を **必ず確認**:

1. シミュレータで滞留再現 → `TripRepository` の `PinRecord.placeName` が DB レベルで埋まっているか
2. 埋まっているなら本チケット（UI 表示）の問題で確定
3. 埋まっていないなら enrichment が動いていない別問題 → 一旦本チケットでは UI 改修のみ進め、enrichment 不発は **別チケット起票**（追加チケット案: S6-013 = enrichPinWithPlaceInfo の発火検証）

ただし jun さんの実機検証では「placeName 空のピンが立った」までしか分かっていないため、**UI 改修だけでも「取得失敗」が見えるようになり大幅 UX 改善** になる（推測ではなく事実が画面に出る）。

### 既存 `RestoredPin` 構造体の所在

`MapView.swift` 内で定義されている `RestoredPin` を拡張するか、`Models/RestoredPin.swift` に独立ファイル化するかは dev-1 判断。既存の利用箇所（`RootView` / `MapView`）に追従すること。
