### QA-S5-003（Info.plist 運用整理 / Google Drive 限定）

- [ ] `.example` ファイルには「ここにあなたの Google Cloud Console で取得した OAuth クライアント ID を入れてください」のコメントが入っている
- [ ] `README.md` または `.scrum/notes/oauth-setup.md` に「初回セットアップ手順」が記載されている

## 技術メモ

### QA-S5-004 の背景

- Sprint 5 retro で「実害は小さい」と判定済（リトライキューが CSV 失敗時に空回りする可能性があったが、実運用で稀）
- Sprint 6 で「最終スプリントなのでまとめて解消」と判断

### QA-S5-003 の背景

- Sprint 5 でユニットテストはプレースホルダー値で動くが、実 OAuth テストには実値が必要
- jun さん側で実 OAuth テストする際に、毎回 plist を手動で書き換える運用は不便
- `.gitignore` + `.example` パターン化で「リポジトリには placeholder のみ、ローカルには実値を上書きコピー」の運用に統一

### 実装手順

1. `.gitignore` に `Resources/GoogleDriveOAuth-Info.plist` を追加（既にあれば確認のみ）
2. 既存 plist が tracked なら `git rm --cached` で untracked 化（jun さん承認後にメインで実施 / Dev は手順書に書くだけ）
3. `Resources/GoogleDriveOAuth-Info.plist.example` を新規作成（プレースホルダー入り）
4. README または `.scrum/notes/oauth-setup.md` にセットアップ手順記載

### Dropbox を omit する理由（再掲）

- jun さん指示で Sprint 6 は Dropbox を扱わない（個人利用は Google Drive のみで十分）
- 商用化判断時に再検討。`CloudStorageProvider` プロトコルは Sprint 5 で抽象化済のため、追加コストは低い
