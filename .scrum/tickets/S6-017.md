## ユーザーストーリー

ユーザー（jun さん）として、**自宅を出た瞬間から（70m 圏を出た直後から）移動が記録されてほしい**。なぜなら、徒歩で 300m 先のショッピングモールに行ったり、車で出かける際の最初の数百メートルが「自宅近くだから」という理由で抜け落ちると、移動ログの目的（実際に通った経路の完全な記録）が成立せず、特に「家から徒歩圏の店舗」「家から近い目的地」が DB から欠落するという致命的体験を生むから。

---

## 背景（実機検証 / 2026-05-12〜13）

S6-016 完了後、jun さんが iPhone 16 Pro 実機で 2026-05-12〜13 に行った実利用検証で発覚した致命バグ。

### 観測された事象

- **事象 1（徒歩）**: 自宅から直線距離 **300m のショッピングモールに歩いて行った** → まったく記録されなかった
- **事象 2（車）**: 車で出かけた際、**家を出てから 500m 分くらいは記録されない**（その後の経路は記録される）
- 設定: 自宅判定半径は **70m**（デフォルト 100m より狭い値で jun さんが運用）

### 期待される挙動

- 自宅 70m 圏外に出た瞬間に通常 GPS が起動して移動の記録が始まる

### 実際の挙動

- 自宅 70m を出てから **500m〜1km 移動するまで何も記録されない**
- 徒歩 300m 圏内のショッピングモールはまったく記録されない（500m 配信距離未満のため）

---

## 根本原因（メイン代行特定済）

**[`GPSLogger/Services/Location/LocationService.swift:274-285`](../../GPSLogger/Services/Location/LocationService.swift#L274-L285) の `startSignificantChangesIfHome`** が、自宅滞在中に通常 GPS を完全に停止して SLC のみに切替えている:

```swift
func startSignificantChangesIfHome() {
    guard let settings = appSettings, settings.homeLocation != nil else { return }
    guard !isMonitoringSignificantChanges else { return }
    // 通常 GPS は停止
    if isUpdating {
        manager.stopUpdatingLocation()
        isUpdating = false
    }
    manager.startMonitoringSignificantLocationChanges()
    isMonitoringSignificantChanges = true
    Self.logger.info("SLC 開始（自宅滞在中の省電力モード）")
}
```

S3-006 で「自宅滞在中は通常 GPS を停止し SLC のみに切替えてバッテリー節約」を実装した。しかし Apple の SLC（Significant Location Changes）仕様は「**500m〜1km 以上動かないと配信されない**」ため、以下の「SLC 空白ウィンドウ」が発生する:

| 状況 | 結果 |
|------|-----|
| 自宅 70m 圏内（`atHome`） | 通常 GPS 停止、SLC のみ |
| **自宅を出て 70m 〜 500m**（**空白ウィンドウ**） | **SLC は配信されず → 位置情報なし → `lastHomeState` は `.atHome` のまま、`handleHomeStateTransition` が発火しない → 通常 GPS も再開されない** |
| 自宅 500m〜1km | ようやく SLC 配信 → `.away` 判定 → 通常 GPS 再開 |

この「空白ウィンドウ」で jun さんの 2 件の症状が完全に説明できる:

- 徒歩 300m のショッピングモール（**SLC 配信距離未満**）→ そもそも `.away` 遷移が発火しないため、まったく記録されない
- 車で出発 → 最初の 500m〜1km が SLC 待ちで記録されない

### S3-006 / S6-005 / S6-015 / S6-016 が拾えなかった理由

- **S3-006**: シミュレータでは SLC の 500m〜1km 配信距離制約が再現されにくく、テストが通ってしまった
- **S6-005**（バッテリー最適化）: 動的精度切替の経路だけを検証していたため、atHome 中の SLC のみモードは触らなかった
- **S6-015 / S6-016**: タスクキル後の SLC 起床経路の修正に集中していたため、**通常起動中の atHome → away 経路** は射程外だった

---

## 修正方針（dev-2 並行実装中 / jun さん承認済「方針 A」）

`atHome` 中も **通常 GPS を維持**するが、**低精度・大 distanceFilter** で省電力化する:

```swift
func startSignificantChangesIfHome() {
    guard let settings = appSettings, settings.homeLocation != nil else { return }
    // SLC は使わない。低精度・大 distanceFilter で通常 GPS を維持。
    // これにより自宅 70m を出た瞬間に didUpdateLocations が発火する。
    manager.desiredAccuracy = kCLLocationAccuracyHundredMeters
    manager.distanceFilter = 100  // 100m
    if !isUpdating {
        manager.startUpdatingLocation()
        isUpdating = true
    }
}
```

### この設計が成立する理由

- **家の中で動かない時**: `distanceFilter=100m` のため CLLocationManager が配信しない → 実質バッテリー消費ゼロ
- **家を出た瞬間**（70m 外）: `didUpdateLocations` 発火 → 通常の `handleHomeStateTransition` 経路で `.atHome` → `.away` 遷移を検出 → 通常精度に戻す
- **`stopSignificantChanges` 側**: 名前と中身を整合させる（SLC を止めるのではなく、精度設定を元に戻す or `BatteryAdaptiveLocationPolicy` に委ねる）

### トレードオフ（CLAUDE.md 記載の懸念との整合）

CLAUDE.md には「常時起動の場合、バッテリー消費が多くなり過ぎることが懸念」とある。本修正は以下のトレードオフを許容する判断:

| 項目 | 修正前（S3-006） | 修正後（S6-017） |
|------|-----------------|-----------------|
| 家の中で動かない時のバッテリー | 限りなくゼロ（SLC のみ） | ほぼゼロ（`distanceFilter=100m` で配信抑止） |
| 家を出た直後の記録欠落 | **70m → 500m〜1km まで欠落（致命）** | **欠落なし** |
| 家を出た直後の検出遅延 | 数分〜数十分（500m〜1km 移動待ち） | 即時（次の didUpdateLocations） |

致命度として「家を出ても記録されない」のほうが圧倒的に大きいため、家の中での僅かなバッテリー消費を許容する（ただし `distanceFilter=100m` で実質ゼロにできる見込み）。
