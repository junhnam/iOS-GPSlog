## ユーザーストーリー
開発者として、アプリ全体で SwiftData の永続化コンテナを安全に共有したい。なぜなら全機能から一貫したDBアクセスを行うため。

## 受け入れ条件
- [ ] `GPSLogger/Services/Persistence/PersistenceController.swift` を新規作成
  - `static let shared: PersistenceController` を持つ
  - `let container: ModelContainer` を保持し、TripRecord / RoutePoint / PinRecord を schema に登録
  - 失敗時は `fatalError` ではなく warning ログを出してインメモリコンテナにフォールバック（起動継続）
- [ ] `GPSLoggerApp.swift` を修正し、`WindowGroup { RootView() }.modelContainer(PersistenceController.shared.container)` を適用
- [ ] テスト用に `static func makeInMemoryContainer() throws -> ModelContainer` を提供（XCTest から呼べる）
- [ ] `GPSLoggerTests/PersistenceControllerTests.swift` を追加し、以下を検証
  - インメモリコンテナを生成して TripRecord を1件 insert → fetch で取得できる
  - 同日付の TripRecord を2件 insert すると、ユニーク制約違反が検出される（または重複が排除される）
- [ ] `xcodebuild test` がパスする

## 技術メモ
- SwiftData は iOS 17+。本プロジェクトは iOS 26+ なので問題なし
- `ModelContainer(for: TripRecord.self, RoutePoint.self, PinRecord.self, configurations: ...)` で構築
- 本番用は `ModelConfiguration(isStoredInMemoryOnly: false)`、テスト用は `isStoredInMemoryOnly: true`
- 永続化先は SwiftData 既定（Application Support 配下）。Sprint 6 の DB自動消去機能まではパス指定不要
- インメモリフォールバック理由: 初回起動時のスキーママイグレーション失敗時にもアプリがクラッシュせず、最低限の操作を継続できるようにするため
